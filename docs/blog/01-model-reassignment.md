# 7B 모델에게 소설을 맡겼다가, 분류기로 강등시킨 이야기

> AI가 서사를 만드는 게임을 만들었다. 그런데 재미가 없었다.
> 원인을 찾아 들어갔더니, 문제는 게임 설계가 아니라 **모델이 글을 못 쓴다는 것**이었다.
> 이 글은 그걸 측정으로 확인하고, 모델의 역할을 바꾼 기록이다.

---

## 만들던 것

`Aetheria 2099` — 한국어 사이버펑크 텍스트 어드벤처다. 플레이어는 기억 브로커
제인이 되어 도시의 진실이 담긴 칩 #00을 두고 세 세력 사이에서 선택한다.

기술적으로 자랑하고 싶었던 건 이거였다:

- Claude를 **교사**로 삼아 데이터를 증류하고
- **Qwen2.5-7B**를 QLoRA로 파인튜닝해서
- 로컬 Ollama로 돌린다 — **API 비용 0원, 완전 오프라인**

그리고 그 모델이 매 턴 나레이션·대사·선택지 3개를 JSON으로 만들어냈다.
홀드아웃 40문항 평가에서 **스키마 준수율 91.8%**. 숫자만 보면 잘 되고 있었다.

---

## 그런데 재미가 없었다

직접 플레이해보고 나온 피드백은 세 줄이었다.

> 문장이 안 읽힌다 / 선택이 무의미하게 느껴진다 / 그냥 밋밋하다

처음엔 게임 설계 문제라고 생각했다. 그래서 시스템을 고쳤다.

- 매 턴 자동으로 오르는 **추적 시계**를 넣어 긴장을 만들고
- 선택지에 **판돈 태그**(추적↑↑ / 추적↓)를 붙여 무게를 노출하고
- 증거 제시를 **추리 퍼즐**로 바꿨다

전부 실제 개선이었고, 각각 측정으로 검증했다. 그런데 재미없다는 말은 그대로였다.

---

## 진짜 원인

플레이어가 화면에서 실제로 하는 일은 **글을 읽는 것**이다. 그 글이 이랬다.

```
제인이 배달원의 품에서 무게를 쥐어:

내가 네 옆에 있어. 그건… 중요하지 않아, 살려고 하든 재우기 위해 있나요.

이건 시간 낭비야. 팔려고 하지 마, 판이나올 거면 네 손에 담겨 있어.

제인이 낙찰자들이 틈으로 빠져나가려 하며 벽에 몸을 밀어붙인다.
```

전부 실제 출력이다. **뜻이 통하지 않는다.**

스키마는 91.8%로 잘 지킨다. `narration`도 있고 `npc_response`도 있고 선택지도
정확히 3개다. **형식은 완벽한데 내용이 없다.**

여기서 중요한 걸 하나 깨달았다. 내가 측정하던 91.8%는 **"JSON을 잘 뱉는가"**였지
**"글이 읽히는가"**가 아니었다. 지표가 목표를 대변하지 못하고 있었다.

그리고 "선택이 무의미하다"도 같은 뿌리였다. 도발을 하든 잠행을 하든 모델이
비슷한 뭉개진 문장을 뱉으니, **게이지는 움직여도 글이 안 변한다.** 플레이어
입장에선 아무것도 안 바뀐 것이다.

---

## 길이 문제인가? — 측정으로 가설 죽이기

"문장을 압축하면 낫지 않을까" 싶어서 재봤다.

| | 중앙값 | 최대 |
|---|---|---|
| 나레이션 | **59자** | 78자 |
| 대사 | **72자** | 125자 |

이미 짧았다. 타이핑 연출도 9ms/자라 72자 대사가 0.65초면 다 뜬다.
**길이도 속도도 원인이 아니었다.** 여기서 압축을 했다면 없는 문제를 고치면서
서사만 빈약해졌을 것이다.

대신 다른 숫자가 눈에 들어왔다. **턴당 생성 시간 중앙값 11.2초.**
0.65초짜리 텍스트를 읽으려고 11초를 기다리는 구조였다.

---

## 결정: 화자를 사람으로 바꾼다

재학습으로 해결되지 않는다고 판단했다. 이미 두 번 실패한 상태였다.

- **v4**: 데이터를 늘렸는데 에폭을 줄여서 언더핏 (90.4%)
- **v5**: 반대로 과교정해서 과학습 (57.5%) — 인사말에도 게임 JSON만 뱉었다

무엇보다, 재학습으로 올라가는 건 **형식 준수율이지 문장력이 아니다.**
7B가 한국어 산문을 쓰게 만드는 건 다른 차원의 문제다.

그래서 본편 18개 씬을 **전부 손으로 썼다.** 씬마다 도입부 + 선택지 3개 +
**선택별 반응**을 쓴다. 같은 장면을 비교하면 이렇다.

**모델이 쓴 것:**

```
제인이 미매각 칩의 존재를 렌에게 재추진하자, 대담한프로그래머가 표정 하나 흔들린다.
렌 — "이건 시간 낭비야. 팔려고 하지 마, 판이나올 거면 네 손에 담겨 있어."
```

**손으로 쓴 것:**

```
렌이 칩을 슬롯에 밀어 넣는다. 단말이 파랗게 깨어난다. 그가 화면을 3초쯤 본다.
그리고 아무 말 없이 칩을 빼서 손바닥 위에 올려놓는다. 파란 빛이 그의 손금을 타고 흐른다.

렌 — "제인. 이거 어디서 주웠는지는 안 물어볼게. …근데 값을 못 매기겠다.
      그건 둘 중 하나야. 쓰레기거나, 이 도시 전체보다 비싸거나."
```

차이는 문장력이 아니다. 아래엔 **"3초쯤 본다"는 정적**이 있고, 렌이 값을 못
매긴다는 **캐릭터의 균열**이 있고, 다음이 궁금해지는 **갈고리**가 있다.

## 그럼 모델은 버리는가? — 아니다

여기가 이 글의 핵심이다. 모델을 빼는 대신 **모델이 실제로 잘하는 일**을 찾았다.

자유 입력(플레이어가 직접 타이핑하는 행동·질문)은 미리 쓸 수 없다. 그런데
자세히 보면 거기서 필요한 건 두 가지로 나뉜다.

1. **"무엇을 하려는가 / 무엇을 묻는가"를 판별** — 분류 문제
2. **그에 대한 문장** — 생성 문제

**모델은 1을 잘한다.** 실측해봤다.

```js
// 플레이어 입력 → authoring 된 선택지 중 하나로 분류
const prompt = `당신은 게임의 의도 분류기다.
플레이어의 행동이 아래 선택지 중 하나와 "같은 의도"이면 그 번호를 출력한다.
선택지들과 아무 관련도 없는 엉뚱한 행동이면 반드시 -1을 출력한다.
번호만 출력하고 다른 말은 하지 않는다.
...`

// temperature 0, num_predict 5 — 숫자 하나면 된다
```

정상 입력 10건에 **10/10**. 응답도 1초 안쪽이다.
"렌한테 사실대로 다 털어놓는다" → 솔직 선택지. "그냥 쓰레기장에서 주웠다고 해"
→ 거짓말 선택지. 정확했다.

### 함정 하나

처음엔 "갑자기 춤을 추기 시작한다"가 **거짓말 선택지로 매핑**됐다.
모델이 "해당 없음(-1)"을 거의 쓰지 않고 아무 데나 억지로 붙였다.

프롬프트에 **-1 예시 두 줄**을 넣으니 10/14 → 12/14로 올랐다.

```
예시:
행동: 노래를 부르며 춤을 춘다
번호: -1
행동: 점심으로 뭘 먹을지 고민한다
번호: -1
```

few-shot 두 줄의 값어치가 이렇게 크다.

## 생성은 여전히 못 한다 — 그래서 게이트를 세웠다

준비된 화제(20개) 밖의 질문에는 모델이 답을 시도한다. 다만 **품질 게이트를
통과한 것만** 화면에 내보낸다.

```js
export function answerPassesGate(text, hasGarbleFn) {
  const t = String(text || '').trim()
  if (t.length < 8 || t.length > 110) return false
  if (/[{}\[\]"]|npc_|_change|story_branch/.test(t)) return false  // JSON 누출
  if (/(.)\1{3,}|[*#~`|]/.test(t)) return false                    // 디코딩 붕괴 신호
  if (INSTRUCTION_LEAK.test(t)) return false                       // 프롬프트 지시 누출
  if (hasGarbleFn && hasGarbleFn(t)) return false                  // 깨진 토큰·한자
  const sentences = t.split(/[.!?…]+/).filter((x) => x.trim().length > 1)
  if (sentences.length > 3) return false
  const hangul = (t.match(/[가-힣]/g) || []).length
  return hangul / t.length >= 0.55
}
```

`INSTRUCTION_LEAK`이 특히 필요했다. 모델이 **자기가 받은 명령을 그대로 뱉는
일이 잦았다.**

```
"…시체가 붙은 물건은 값이 두 배야. 위험 프리미엄. 짧게만 답해."
"규정은 규정이다. 모르겠나? 다시 묻지 마라"
```

게이트를 통과한 비율은 **3/8**. 나머지는 손으로 쓴 회피 대사로 떨어진다.
낮은 숫자지만, 중요한 건 **깨진 문장이 화면에 절대 나가지 않는다**는 것이다.

그리고 이 3/8이 다음 재학습의 **목표 지표**가 된다. 같은 8문항, 같은 게이트로
재면 개선 여부를 바로 안다.

## 결과

| | 전 | 후 |
|---|---|---|
| 화면에 나가는 글 | 모델 생성 | **사람이 씀** (18씬, 1.9만 자) |
| 클릭 → 반영 | 11.2초 | **0.5초** (의도적인 쉼) |
| 자유 입력 의도 판별 | — | 모델, **10/10** |
| 자유 입력 답변 | 깨진 문장 | 손으로 쓴 답변 20주제 × 4인물 = 80개 |
| 자동 플레이테스트 5판 | 9분 | **90초** |

모델을 뺀 게 아니다. **글쓰기에서 판단으로 자리를 옮겼을 뿐이다.**

## 배운 것

**1. 지표가 목표를 대변하는지 의심해야 한다.**
스키마 준수율 91.8%는 진짜 숫자였지만 "재미"와는 상관이 없었다. 나는 측정
가능한 걸 측정하고 있었지, 중요한 걸 측정하고 있지 않았다.

**2. 모델이 못 하는 일을 인정하는 데도 측정이 필요하다.**
"7B는 원래 글 못 써"는 감이다. "정상 입력 분류 10/10, 답변 생성 게이트 통과
3/8"은 판단 근거다. 후자가 있어야 어디에 배치할지 정할 수 있다.

**3. 가설은 자주 틀린다.**
나는 "문장을 압축하면 낫다"고 생각했고 틀렸다(이미 59자였다).
"num_predict를 줄이면 빨라진다"고 생각했고 틀렸다(출력이 이미 250토큰이라
상한에 안 닿았다). 재보기 전에 고쳤다면 둘 다 헛수고였다.

**4. LLM 프로덕트의 일은 대부분 "모델 밖"에 있다.**
분류 프롬프트의 few-shot 두 줄, 품질 게이트의 정규식, 실패했을 때 떨어질
자리. 모델 자체를 건드리지 않고도 체감 품질은 크게 달라진다.
