# 같은 학습 결과가 81%와 88.6%로 갈렸다 — 이중 양자화 함정

> 학습은 끝났다. 어댑터도 잘 나왔다.
> 그런데 **모델을 내보내는 방식만 바꿨더니 점수가 7.6%p 움직였다.**
> 학습을 한 번도 다시 돌리지 않고서.

---

## 양자화가 뭔지부터

7B 모델은 파라미터가 70억 개다. 이걸 원래 정밀도(16비트)로 들고 있으면 14GB쯤 된다.
개인 PC에서 돌리기엔 부담스럽다.

그래서 **양자화**를 한다. 숫자의 정밀도를 낮춰서 크기를 줄이는 것이다.
16비트를 4비트로 줄이면 용량이 4분의 1이 된다. 대신 숫자가 살짝 뭉개진다.

사진을 JPEG로 저장하는 것과 비슷하다. 용량은 줄고, 화질은 조금 떨어진다.
적당히 하면 눈에 잘 안 띈다.

**QLoRA**는 이 성질을 이용한 학습 방법이다. 큰 모델을 4비트로 눌러 메모리에 올려두고,
그 위에 작은 부품(LoRA 어댑터)만 학습한다. 덕분에 맥에서도 7B를 튜닝할 수 있다.

---

## 함정: JPEG를 JPEG로 다시 저장하기

학습이 끝나면 어댑터를 원본 모델에 합쳐서 하나의 모델로 만들어야 한다.
그리고 Ollama에서 쓰려면 다시 4비트로 양자화해야 한다.

여기서 무심코 이렇게 했다.

```
4비트로 눌린 모델 + 어댑터  →  합치기  →  다시 4비트로 양자화
```

문제가 보이는가. **이미 한 번 뭉개진 것을 또 뭉갠 것이다.**

JPEG로 저장한 사진을 열어서 다시 JPEG로 저장하는 것과 같다.
한 번이면 티가 안 나지만, 두 번 겹치면 손실이 쌓인다.

---

## 고친 방법: 되돌린 다음에 한 번만 누르기

합치기 전에 **원래 정밀도로 되돌린다.** 그다음 딱 한 번만 양자화한다.

```
4비트 모델 + 어댑터  →  16비트로 되돌려 합치기  →  4비트로 양자화 (한 번만)
```

명령으로는 `--dequantize` 옵션 하나 차이다.

```bash
# 어댑터를 합치면서 16비트로 되돌린다
python3 -m mlx_lm fuse --model qwen7b-4bit --adapter-path adapters \
  --save-path fused --dequantize

# 합쳐진 16비트 모델을 여기서 처음이자 마지막으로 양자화한다
ollama create aetheria -q q4_K_M -f Modelfile
```

**결과: 준수율 81% → 88.6%.** 학습은 똑같은 것을 썼다. 내보내는 순서만 바꿨다.

## 곁다리로 알게 된 것

### 내보내기 명령이 이 모델을 지원하지 않았다

MLX에는 GGUF 형식으로 바로 내보내는 옵션이 있는데, Qwen 계열은 지원하지 않는다.
그래서 "16비트로 합쳐서 내보낸 뒤, Ollama에게 양자화를 맡기는" 길로 갔다.
막혀서 돌아간 길이 결과적으로 더 나은 길이었다.

### 지금 돌고 있는 게 정말 내가 학습시킨 모델인가

다른 버전에서 점수가 이상하게 낮게 나왔을 때, 가장 먼저 의심한 건
"합치기가 실패해서 원본 모델이 그대로 나온 것 아닌가"였다.

이건 확인할 수 있다. 모델 파일 안에 만든 사람과 도구 이름이 적혀 있다.
거기에 내 이름이 찍혀 있으면 파인튜닝은 제대로 된 것이다.
확인하고 나서야 다른 원인을 찾으러 갈 수 있었다.

### 대화 형식을 빼먹으면 조용히 손해 본다

모델은 "누가 한 말인지"를 표시하는 형식을 정해두고 학습한다.
내보낼 때 그 형식을 같이 넣지 않으면, 모델은 역할 구분 없이 뭉쳐진 글을 받는다.

이걸 제대로 채워 넣었더니 점수가 1.4%p 올랐다.
찾던 큰 원인은 아니었지만, 공짜로 얻는 1.4%p였다.

## 배운 것

**1. 학습만큼 내보내기도 결과를 바꾼다.**
7.6%p면 학습 설정을 크게 손봐야 나오는 차이다. 그걸 명령어 옵션 하나가 만들었다.
모델을 만드는 일은 학습에서 끝나지 않는다.

**2. 손실이 겹치는 지점을 의심해야 한다.**
각 단계는 저마다 "조금만" 잃는다. 문제는 그게 **쌓인다**는 것이다.
되돌릴 수 있는 지점이 있으면 되돌리고, 잃는 일은 마지막에 한 번만 한다.

**3. 숫자가 이상하면 "내가 보고 있는 게 맞는 것인가"부터 확인한다.**
모델 성능을 의심하기 전에, 그 모델이 정말 내가 학습시킨 그것인지 먼저 봐야 한다.
아니라면 그 뒤의 분석은 전부 헛수고다.
